# 金屬零件計數（AOI）

## 1. 專案主旨與功能

以傳統影像處理（不使用機器學習）計算單張圖片中的金屬零件數量，附 PySide6 操作介面。

主要功能：

- **零件計數**：依拍攝背景選擇「淺色背景」或「深色背景」演算法，自動辨識並計數零件
- **ROI 框選**：只計數重心在框選範圍內的零件
- **步驟可調**：每個影像處理步驟都可啟用 / 停用、調參數、查看中間結果
- **結果檢視與匯出**：二值化圖、辨識結果圖、單一零件突顯；匯出 `*_binary.png`、`*_result.png`、`*_parts.csv`
- **鏡像（翻面）配對**：模擬零件翻面拍攝，找出原圖與鏡像圖中哪些零件是同一片
- **鏡像位移測試**：在鏡像之外再加上整張平移，批次驗證配對演算法在各種位移情境下是否可靠

### 執行方式

```bash
uv run metalpartidbetification
```

1. 「選擇圖片資料夾…」→ 點選清單中的圖片，會自動辨識；左側「演算法」下拉選單依拍攝背景選擇「淺色背景」或「深色背景」
2. 「原圖 / ROI」分頁：按住左鍵拖曳框選辨識範圍（只計數重心在框內的零件），「清除 ROI」恢復整張圖
3. 「二值化結果」、「辨識結果」分頁查看輸出；右側清單點選零件 → 單獨突顯
4. 左側控制選單依執行順序列出各技術，可啟用/停用、調參數、按「查看」看該步驟中間結果
5. 「辨識結果」分頁 →「匯出結果…」選擇輸出資料夾，輸出 `*_binary.png`、`*_result.png`、`*_parts.csv`

## 2. 怎麼做到的（口語說明）

一張照片裡擺了很多金屬零件，程式要做的事就是「把每一片零件分開，然後數有幾片」。

1. **先把零件和背景分開**：把照片轉成黑白，讓零件變白、背景變黑。背景顏色不同，做法也不同——
   淺色背景時零件和背景亮度很接近，所以先加強局部對比再分；深色背景時零件本來就比較亮，直接用亮度分就好。
2. **清掉雜點、補好破洞**：用形態學處理去掉灰塵造成的小白點，把零件內部的小黑洞補起來。
3. **把黏在一起的零件切開**：零件常常靠在一起，看起來像一大塊。程式先找出每片零件的「中心」，
   再像水往低處流一樣（分水嶺）從中心往外長，長到彼此碰到的地方就是分界線。
4. **檢查每一塊是不是剛好一片**：替每個輪廓打信心分數。程式會從同一張圖裡挑出最有把握的「完整單片」當樣板，
   只拿它去比對那些看起來可疑的輪廓（可能是好幾片黏在一起，或只是碎片），判斷裡面到底有幾片。
5. **合併結果並計數**：把確定的零件和樣板比對出的零件合起來，得到最後數量。

**翻面配對**則是：把圖片鏡像翻轉（模擬零件被翻面後再拍一次），用同一套方法辨識，
再只靠「零件輪廓長怎樣、在哪個位置」來配對——先猜是怎麼翻的，再用輪廓重疊程度一對一配對，最後對齊中心細看輪廓確認。
**位移測試**則在翻面之外再故意把整張圖往不同方向移動不同距離，檢查配對會不會出錯；最重要的要求是「很有把握卻配錯」必須是 0 次。

## 4. 系統架構

```
src/metalpartidbetification/
  core/        資料模型、步驟介面(PipelineStep)、插件註冊、Pipeline 引擎（不依賴 GUI）
  algorithms/
    light/     淺色背景演算法（各步驟插件；presets.py 定義執行順序）
    dark/      深色背景演算法（與 light 完全獨立，不共用任何演算法程式碼）
    registry.py 可選用的演算法組清單
  matching/    鏡像（翻面）配對演算法（只依賴 core，不引用 algorithms、imaging）
  imaging/     模擬翻面（鏡像 + 整張平移），只供 app 層與 shift_test 使用
  shift_test/  鏡像位移測試核心：情境、執行、報告（不依賴 GUI）
  fileio/      圖片讀寫（支援中文路徑）、結果匯出
  rendering/   結果圖繪製（全部標註 / 單一零件突顯）
  app/         流程協調（GUI 只呼叫這一層）
  gui/         PySide6 介面：main_window（分頁切換）、recognition_page（辨識頁）、shift_test_page（鏡像位移測試頁）
```

依賴方向：`gui → app → (algorithms, matching, imaging, fileio, rendering) → core`；`algorithms/light`、`algorithms/dark`、`matching` 互不引用
（`tests/test_architecture.py` 會自動檢查）。

新增影像技術：在對應的演算法子套件寫一個繼承 `PipelineStep` 的類別並加上 `@register_step`，
宣告 `requires` / `provides` / `param_specs`，再把 key 加入該套件 `presets.py` 的 `DEFAULT_ORDER`；
GUI 會依 `param_specs` 自動產生參數輸入元件。新增一整組演算法：建立新子套件並登記到 `algorithms/registry.py`。

## 5. 影像辨識流程

**淺色背景**（零件與背景亮度接近）：前處理（灰階 → 雙邊濾波）→ ① 局部對比 → ② 二值化 → ③ 形態學去雜訊
→ ④ 距離轉換找種子 → ⑤ 標記式分水嶺 → ⑥ 區域分類 → ⑦ 依邊界強度合併 → ⑧ Blob 分析
→ ⑨ 輪廓信心評分（選樣板）→ ⑩ 樣板比對（只處理有疑慮輪廓）→ ⑪ 結果合併與計數

**深色背景**（零件明顯比背景亮）：前處理（灰階 → 高斯模糊）→ ① 亮度二值化 → ② 形態學（去灰塵、補孔）
→ ③ 排除邊界區域 → ④ 接縫切割（黑帽運算）→ ⑤ 距離轉換 + 分水嶺 → ⑥ Blob 分析
→ ⑦ 輪廓信心評分（選樣板）→ ⑧ 樣板比對（只處理有疑慮輪廓）→ ⑨ 結果合併與計數

**自我樣板比對**：每次辨識從同一張圖中挑出最有把握的「完整單片」輪廓（鏡像對稱度最高）當樣板，
只用它去辨識有疑慮的輪廓（疑似多片相連或碎片）；擺放的樣板之間不可重疊（零件不會重疊）。

**鏡像（翻面）配對**：勾選「自動鏡像比對」後，原圖辨識完成會自動產生鏡像（模擬翻面拍攝，本階段無位移）
→ 以同一組演算法辨識鏡像 → 配對演算法只用零件「輪廓與位置」判斷哪些零件是同一片：
① 推估鏡像方向（三種方向比較零件遮罩重疊度）→ ② 輪廓重疊度 + 匈牙利演算法一對一配對
→ ③ 以中心點對齊的輪廓細節驗證。「鏡像結果」「配對比較」分頁與右下「鏡像配對」清單顯示結果、
分段耗時與總耗時；「評估用」資訊以模擬參數計算，配對演算法本身拿不到。「儲存鏡像圖…」可存到指定位置。

**鏡像位移測試**（視窗上方分頁「鏡像位移測試」）：沿用辨識頁目前的圖片、演算法與參數（唯讀；測試期間鎖定辨識頁），
選擇鏡像方向（預設左右）、平移方位（8 方向可複選）與位移幅度（可多個，0～100 px；超過搜尋範圍 50 px 者僅供對照），
按「開始測試」後逐一執行：鏡像＋整張平移（單一背景色補邊、斜向以直線距離計算）→ 辨識 → 配對（含位移估算）→ 逐片判定。
判定顏色：綠＝高信心配對正確、黃＝無法確定、紅＝疑似可配對到多個零件（連線到每個候選）、灰＝無法對應；
ROI 不套用到辨識，只用於警告：ROI!＝位移可能過大、LOST＝可能遺失（鏡像圖的 ROI 跟著鏡像、不跟著位移）。
情境總表中「高信心但配錯」必須為 0；結果可匯出為標記結果圖、逐片明細 CSV、情境總表 CSV 與摘要 HTML。
